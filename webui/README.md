# Zanevka Newsbot — WebUI

Существующий HTML/CSS/JavaScript-интерфейс подключён к локальному
`webui_server.py` (Flask/Waitress). Соседний дизайн, подписи, иконки и расположение
элементов сохранены; представление журнала описано ниже.
Отдельная `login.html` использует исходную тему `original`: именно она
первой загружается в style.css/themes.css, без изменения порядка тем.

Запуск, примеры Windows/Unix, настройка доступа, HTTPS/префикс, Caddy/Apache,
cron и **точные ручные команды API**: [DEPLOYMENT.md](DEPLOYMENT.md).
Полный HTTP-контракт: [API.md](API.md).

## Что подключено

- «Запустить сейчас» вызывает POST api/run один раз, сразу блокируется,
  учитывает старт до появления флага, внешние запуски и секундную задержку
  после завершения. Режим выбирает prelaunch, включая немедленный повтор
  по delayed.publish. Код 202 не означает публикацию; результат — в журнале.
- Переключатель расписания меняет Unix-флаг flags/.newsbot.disabled для будущих
  cron-запусков. Текущая обработка продолжается, ручная кнопка работает.
  На Windows он недоступен; статус сообщает Windows/manual.
- Форма загружается из config.py и до успешной загрузки не сохраняется.
  Передаются только изменённые разрешённые поля и ревизия; секреты GET не
  возвращает, пустое поле сохраняет значение, после сохранения ввод очищается.
  Изменения применятся к следующему запуску. Демонстрационный localStorage
  удаляется; локально сохраняется только выбор темы.
- История последних десяти журналов и новые строки идут через общий читатель
  и SSE. Логический блок объединяет заголовок и подробности в одну строку DOM
  с одним многострочным `span.message`. Исходные физические строки, табуляция,
  timestamp, уровни, пустые строки и их порядок сохраняются для экспорта.
  Данные выводятся через textContent.
- Курсор/идентичность строк согласуют историю, разрыв и повторную синхронизацию;
  ошибки и недоступная часть истории явно показываются в существующем журнале.
  Очистка панели не удаляет серверные файлы и не сбрасывает доставку;
  reconnect не возвращает очищенные строки. Новое открытие загружает историю.
- Сохранены фильтры, очистка/восстановление окна, экспорт, ручная прокрутка,
  автоследование, Ctrl+колесо, сброс масштаба, вкладки/двойной клик,
  закрытие, перемещение и изменение размера настроек, переключение тем.
- Потеря сессии ведёт на login, защищённые API при этом возвращают JSON 401.
  Нет деморежима, автоматического входа или новых скрытых контролов.

## Отображение журнала

Группировка использует серверный `block` вместе с файлом и поколением из
`identity`. Одинаковая секунда не склеивает разные блоки или файлы. Поздние SSE-
подробности сразу дополняют свой блок, в том числе при вставленном событии [UI].
Частичный блок сохраняет доступные детали и серверный контекст без выдуманного
заголовка. Лимит панели по-прежнему составляет 10 000 физических записей,
а не 10 000 объединённых блоков. Дедупликация и курсоры работают отдельно.

Перед каждым именем файла, включая первое, CSS даёт две строки интервала;
перед каждым блоком и самостоятельным [UI] — одну строку. Нижние margins,
старый верхний padding и крайние пустые разделители не удваивают интервалы.
Интервалы следуют line-height и масштабу 60–200%. Настоящее имя API формата
`DDMMYYYY_HHMMSS_<6 hex>.txt` сохраняется вместе с горизонтальной `.session-line`.
Длинное имя переносится. Генератор имён и порядок журналов не менялись.

Время выводится явно двумя строками: `HH:MM:SS`, затем `YYYY-MM-DD`, в столбце
`10ch`, также на мобильной ширине. Timestamp бота не преобразуется в часовой
пояс браузера. У [UI] обе части фиксируются одним Date при создании; экспорт
этих сообщений сохраняет прежний формат с одним временем без даты.
Уровень показан один раз сверху, фильтр действует на весь блок. У OK (`success`)
уровень и всё сообщение, включая поздние детали, зелёные через `var(--green)`
(`#9de8ba` в original); время/имя файла сохраняют цвет. WARNING/ERROR/INFO и
переключение тем сохранены. Служебная первая табуляция деталей скрыта только
в представлении; вложенные пробелы, traceback и внутренние переносы остаются.

### Служебные сообщения [UI]

Списки предыдущей отменённой реализации инвертированы:

- **Убраны 10 живых типов:** U01–U07 (вкладки, открытие/сворачивание панели,
  масштаб, фильтр, показ/скрытие секрета), U12 (dirty-уведомление),
  U13 (текст валидации) и U28 (собственное непустое сообщение ошибки API/браузера).
  Статические H01–H03 («Загружено из этого браузера», запрос/завершение
  тестового main.py), а также статические примеры удалённых U отсутствуют в HTML.
- **Сохранены 18 живых типов:** U08–U11 (повторная очистка, очистка,
  восстановление, экспорт), U14–U17 (сохранение/сброс config.py, принятый запуск,
  пояснение cron), U18–U20 (resync, reconnect, усечённая история), U21–U24
  (SSE diagnostic: 64 КиБ, восстановление/ошибка чтения, ранний stderr),
  U25–U27 («Требуется вход.» при 401, «Ошибка API.» без сообщения в ответе,
  «Потеряна связь с API.» без собственного сообщения исключения).

U28 скрыт только из пользовательского журнала [UI] и его экспорта. Исключение
сохраняет исходный message, catch/finally, восстановление контролов и статуса
выполняются. Явные метаданные отличают fallback API и 401 от собственного текста:
совпавший с fallback текст U28 не подменяется уведомлением U25–U27. SSE diagnostic
U21–U24 — отдельный источник и сохраняет непустой stderr. Глобального фильтра
текстов нет, настоящие ERROR/WARNING/OK бота не скрываются. Новых уведомлений нет.

Действия без уведомлений продолжают работать: dirty-состояние формы,
валидация/фокус невалидного поля и блокировка сохранения, вкладки, панель,
масштаб, фильтр и секреты. U09 «Лог очищен.» сохраняет свою кнопку «Вернуть
записи», доступную и после новых SSE-строк; после восстановления кнопка исчезает.
Новые детали очищенного блока не возвращают прежние строки; восстановление
объединяет доступные старые и новые строки без дублей. Экспорт включает U11,
оставленные [UI] и исходные строки бота без визуальных CSS-разделителей.

## API без контролов на текущем сайте

| Функция | Endpoint | Ручная проверка | Отсутствующий контрол / будущая привязка |
| --- | --- | --- | --- |
| Выход | POST api/logout | В том же браузере получить GET api/session, передать csrf_token в X-CSRF-Token и JSON {}; пример в DEPLOYMENT.md | Будущая кнопка выхода; сейчас её нет |
| Полный сброс flags | POST api/debug/reset-flags | Аналогичный POST при простое; списки deleted/errors, конфликт 409 при работе/старте/занятом lock | Будущий отдельный Debug-контрол; сейчас нет кнопки, вкладки или скрытого управления |

Debug сохраняет каталог и существующую .main.lock, удаляет **все** остальные
служебные записи, включая disabled (разрешает будущий cron), delayed.publish,
свободный running и метки пустых журналов. Не восстанавливает почту/партию,
не останавливает процесс и не удаляет журналы. Отдельная страница входа
реализована и к отсутствующим контролам не относится.

## Ограничения до отдельного UI-прохода

Статические подписи про макет/DEMO во вкладке CRON оставлены по прямому запрету
на изменение дизайна/текстов; о реальной семантике сообщает журнал. Поля интервала
и зоны readonly/disabled: API не редактирует crontab. Достоверные expression и
CRON_TZ заполняют существующие места; неподдерживаемое/неизвестное значение не
выдаётся за демонстрационное. Наличие задания не доказывает исправность cron.

Фабричные рабочие настройки не определены. Существующая «По умолчанию»
восстанавливает последние успешно загруженные серверные значения вкладки,
без возврата демонстрационных реквизитов HTML; введённые секреты очищаются.
Её подпись и полноценный выбор фабричного сброса требуют отдельного решения UI.

Буферы ограничены: история до 10 000 строк/4 МиБ, replay 2048 событий, очередь
256; переполнение/старый курсор/смена файлов явно вызывают resync. Новое окно
видит доступную историю; удалённые журналом файлы не исчезают из открытой панели.
SSE heartbeat — 10 секунд, проверка сессии — примерно каждую секунду.
LOG_DIR задаётся локально вне формы; после его ручной смены перезапустите API.

## Проверка

Офлайн: `python probe/check_logging.py`, `python probe/check_webui_api.py`.
Браузерный стенд: `probe/serve_webui_fixture.py` и
`probe/check_webui_browser.py` (опциональный Playwright/Chromium, без добавления
зависимостей в production). Стенд использует временный каталог и подставной
конвейер; настоящие сервисы не вызываются.
`python probe/check_webui_journal.py` дополнительно проверяет блочное
представление, интервалы/время/цвета, лимит физических строк, очистку/resync и
инвертированные [UI] на подменённых API/SSE в настоящем Chromium, без запуска бота.
Актуальный перечень выполненных проверок и ограничения: [VALIDATION.md](VALIDATION.md).

Проверено в Debian 13/Python 3.13.5 и Chromium 154, включая локальный HTTP с
префиксом, вход/выход, две панели, сохранение/секреты, живой журнал и отсутствие
выполнения HTML. Доверенные HTTPS-заголовки проверены на уровне WSGI; реальные
Caddy/Apache/сертификаты, Windows 10 и FreeBSD требуют проверки при деплое.

Правила изменений — webui/AGENTS.md и корневой AGENTS.md. GitHub Pages
со статическими файлами больше не является самостоятельным работающим backend.
