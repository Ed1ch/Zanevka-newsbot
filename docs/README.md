# Документация Zanevka Newsbot

Документация описывает действующее состояние приложения. Исходный код — источник фактической реализации, утверждённые ADR — обязательных архитектурных ограничений. Задачи развития находятся в [GitHub Issues](https://github.com/Ed1ch/Zanevka-newsbot/issues), история изменений — в Git.

## Начало работы

- [README.md](../README.md) — назначение проекта, возможности и среда эксплуатации.
- [AGENTS.md](../AGENTS.md) — обязательные правила работы агентов с репозиторием.

Перед изменениями прочитать AGENTS.md; при нетривиальной задаче также decisions.md. Остальные документы выбирать по области задачи, а не читать весь комплект подряд.

## Карта документов

| Документ | Когда читать |
| --- | --- |
| [decisions.md](decisions.md) | Архитектурные ограничения и утверждённые решения |
| [architecture/system.md](architecture/system.md) | Компоненты, границы модулей, запуск, блокировки, служебное состояние |
| [architecture/pipeline.md](architecture/pipeline.md) | Почта, обработка партии, сопоставление материалов, отсрочка, публикация и ошибки |
| [operations/deployment.md](operations/deployment.md) | Установка, HTTPS, cron, службы, обновление, откат и обслуживание RELEASE |
| [operations/trial-run.md](operations/trial-run.md) | Выбор тестов, команды, распределение ответственности и приёмка |
| [ui/admin.md](ui/admin.md) | Клиентская архитектура, внешний вид и поведение WebUI |
| [ui/api.md](ui/api.md) | Серверная архитектура, авторизация, HTTP, настройки, управление процессом, история и SSE |

При изменении реализации обновлять соответствующий профильный документ в том же изменении. Не дублировать подробности в корневом README, AGENTS.md или других документах; использовать ссылки. Противоречия между кодом и утверждёнными решениями сообщать владельцу, не разрешать их самовольно.
