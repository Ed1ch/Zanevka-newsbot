# Zanevka Newsbot — WebUI

Клиентская часть приложения: HTML, CSS и JavaScript без frontend-фреймворка. Общая архитектура — [system.md](../architecture/system.md), серверный контракт — [api.md](api.md), эксплуатация — [deployment.md](../operations/deployment.md).

## Архитектура

| Файл относительно webui/ | Ответственность |
| --- | --- |
| index.html | Основной интерфейс, журнал, управление ботом и настройки |
| login.html | Форма входа и публичная панель журнала |
| index_files/script.js | Контролы, API, история и SSE, курсоры, журнал, настройки |
| index_files/login.js | Сессия, CSRF, отправка формы, ошибки входа |
| index_files/login-preview.js | Загрузка снимка истории, группировка, обновление и размеры панели |
| index_files/journal-view.js | Общие правила видимости технических строк обоих просмотрщиков |
| index_files/theme_switcher.js | Выбор и переключение темы, сохранение предпочтения |
| index_files/style.css | Основная геометрия, типографика, индикаторы и журнал |
| index_files/login.css | Страница входа и публичный просмотрщик |
| index_files/settings_window.css | Окно настроек |
| index_files/themes.css и другие CSS | Темы, переключатель, оформление контролов и журнала |
| index_files/ | Графические ресурсы, в том числе фон login и иконки |

Браузер использует один origin для HTML, API и SSE, с учётом prefix. Конвейер работает на сервере; клиент не исполняет его и не имитирует обработку. Рабочие настройки и секреты не сохраняются в localStorage.

## Вход и выход

- login.html использует тему original, фон SHeep_edit.webp и виньетку. В широкой раскладке форма слева сверху, просмотрщик справа; отступ 20 px. При ширине до 811 px — одна колонка.
- Форма шириной до 380 px, поля логина и пароля с кнопкой «Войти». Ошибка выводится в login-error; пустая область не резервируется. Сессия и CSRF получаются до отправки формы.
- Публичный просмотрщик получает снимок последних десяти доступных журналов через GET api/logs/preview при открытии и по кнопке обновления. Это не SSE. Данные совпадают с ограниченной серверной историей после входа; разграничение доступа описано в api.md.
- Начальные размеры просмотрщика — до 380 × 300 px с учётом доступного пространства. Нижняя граница меняет высоту, левая — ширину, угол — оба размера; правая граница остаётся на месте. Для границ доступны клавиши стрелок. Шрифт моноширинный 10 px, прокрутка вертикальная, сообщения переносятся, время и уровень не переносятся.
- Кнопка «Выйти» вызывает POST api/logout и возвращает на login. Ошибка выхода показывается рядом с контролом, работающий бот не останавливается. Потеря сессии переводит клиента на login.

## Управление ботом

| Состояние | Индикация |
| --- | --- |
| Идёт запуск или обработка | «Работает», индикатор мигает (.is-running, status-blink) |
| Простой, cron обнаружен и разрешён | «Работает», индикатор не мигает |
| Простой, расписание отключено или не подтверждено | «Остановлен» |
| Простой на Windows | Windows/manual |
| Неизвестное состояние процесса / потеря связи | «Ошибка» |

Мигание включает и промежуток ожидания принятия ручного запуска. Подсказка индикатора уточняет состояние; статическое «Работает» не подтверждает активный процесс или исправность cron.

- «Запустить сейчас» отправляет один POST api/run, блокируется на время запроса/обработки и до разрешения сервером следующего запуска. При принятии запроса выводится «Бот запущен вручную», включается автоследование журналу. HTTP 202 не означает успешную публикацию.
- Режим прохода выбирает лаунчер по delayed.publish; отдельного выбора режима нет.
- Переключатель «Запуск по расписанию» меняет разрешение следующих cron-запусков, не останавливает текущую обработку и не запрещает ручной запуск. На Windows недоступен. Значение переключателя отражает флаг, а не существование cron-задания.
- Вкладка CRON показывает данные обнаруженного задания. Интервал и часовой пояс недоступны для редактирования; неизвестные значения остаются пустыми. Статические подписи про макет в HTML не отражают фактическую серверную семантику.
- Debug реализован только в API; в WebUI нет отдельной кнопки или вкладки для сброса flags.

## Настройки

Настройки почты, WordPress, VK загружаются из config.py через API; сохранение недоступно до успешной загрузки. Передаются только изменённые разрешённые поля и revision. Валидация переводит фокус на невалидное поле нужной вкладки.

Секреты не возвращаются сервером: состояние configured_secrets отображается как описание поля, пустое поле сохраняет значение. Показ/скрытие относится только к введённому пользователем значению. После успешного сохранения ввод секретов очищается. Настройки применяются к следующему запуску.

«По умолчанию» восстанавливает последние загруженные серверные значения активной вкладки, очищает введённые секреты; это не фабричный сброс и не автоматическое сохранение.

Окно настроек поддерживает вкладки, сворачивание, перемещение за активную вкладку или свободное место (в том числе в области прокрутки), изменение размера. Клик вне окна закрывает его без потери введённых значений до следующего открытия.

## Журнал

### Данные и представление

- Основной журнал загружает историю через API и получает новые строки через SSE. Серверный block вместе с файлом и поколением из identity определяет логическую запись: один заголовок и его детали — одна .log-row с многострочным span.message. Одинаковое время не объединяет разные блоки.
- Поздние детали дополняют исходный блок даже после клиентского сообщения [UI]. Частичный блок отображает доступные данные и серверный контекст без придуманного заголовка. Дедупликация по identity/offset и SSE-курсор независимы от группировки.
- Данные вставляются через textContent. Служебная первая табуляция детали скрыта в представлении, остальные отступы и traceback сохраняются. Физические строки, уровни, время и пустые строки сохраняются для экспорта.
- Имя файла DDMMYYYY_HHMMSS_<6 hex>.txt и горизонтальная .session-line отделяют журналы; длинное имя переносится. Перед именем — 2lh, перед блоком — 1lh, включая первую запись. Интервалы масштабируются с текстом.
- Время HH:MM:SS, дата YYYY-MM-DD остаётся в DOM и скрывается CSS в столбце 10ch. Часовой пояс серверного времени не преобразуется. Для [UI] дата и время получаются одним Date, экспорт использует время без даты.
- Уровень показан один раз на блок; фильтр действует на блок целиком. OK — цвет var(--green) для уровня и сообщения, включая поздние детали; WARNING/ERROR используют var(--amber)/var(--coral). Время и имя файла не перекрашиваются.
- Общий journal-view.js скрывает технический блок первого прохода; в повторном проходе сохраняются режим и погашение флага, строка Workflow скрывается. Исходная история и сырой экспорт не изменяются.

### Управление журналом

- Клиент хранит до 10 000 физических записей, не объединённых блоков. Серверные ограничения истории и replay описаны в api.md.
- Очистка панели не удаляет файлы и не сбрасывает учёт доставки. «Вернуть записи» восстанавливает доступные старые и новые строки без дублей, остаётся доступной после новых SSE-событий. Повторная синхронизация не возвращает очищенные записи; новое открытие страницы загружает историю заново.
- Экспорт newsbot-log.txt содержит доступные физические строки панели и оставленные [UI] в исходном порядке, без CSS-разделителей и приветствия. Это не полный архив на диске; фильтр отображения не заменяет исходные записи.
- Прокрутка вверх останавливает автоследование; возврат в конец возобновляет его. Кнопка «К последнему сообщению» справа внизу (80 px от низа) возвращает к последней видимой записи и включает слежение.
- Масштаб 60–200%: Ctrl+колесо — шаг 2%, Ctrl+плюс/минус — 10%, Ctrl+0 — 100%.

### Клиентские сообщения

Клиентские записи группируются под заголовком Newsbot speaking. После загрузки истории, соединения и подтверждённого простоя выводится приветствие: первая строка через 2 секунды, следующие через секунду. Запуск прекращает приветствие до нового открытия; эти записи не экспортируются.

В журнале отображаются сообщения о ручном запуске, сохранении/восстановлении настроек, экспорте, очистке/восстановлении журнала, потере потока и переподключении, усечённой истории, серверные diagnostic и предусмотренные ошибки связи/авторизации. Обычные действия с вкладками, окном, масштабом, фильтрами, секретными полями и dirty/validation не создают записи.

Собственные непустые тексты исключений API/браузера не добавляются в [UI] и экспорт; исключение сохраняет message, обработчики восстанавливают состояние контролов. Явное уведомление о необходимости входа и fallback «Ошибка API.» / «Потеряна связь с API.» при отсутствии собственного сообщения выводятся. Метаданные отличают fallback от совпадающего по тексту собственного исключения. Ошибки входа/выхода имеют отдельные области. Серверные SSE diagnostic — независимый источник; непустой stderr и реальные уровни ERROR/WARNING/OK бота не фильтруются по тексту. Штатный resync не создаёт отдельного сообщения.

## Темы

Основная страница выбирает одну из четырёх тем (original, purple-edge, deep-ocean, dark-amethyst) случайно, исключая последнюю показанную. Клик по заголовку циклически переключает темы; localStorage хранит только предпочтение темы. Страница входа использует original. Подпись .identity-description имеет постоянную opacity: .48, не зависит от состояния расписания.
