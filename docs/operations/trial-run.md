# Zanevka Newsbot — тестирование и приёмка

Регламент проверки изменений, а не журнал выполненных тестов. Правила разработки — [AGENTS.md](../../AGENTS.md); эксплуатационная приёмка — [deployment.md](deployment.md).

## Ответственность сред

| Среда | Назначение |
| --- | --- |
| Codex Cloud | Анализ, реализация, review diff и адресные проверки изменённой логики |
| GitHub Actions (при наличии применимых workflow) | Независимая автоматическая регрессия конкретного SHA |
| RELEASE | Развёртывание согласованной версии, визуальная и эксплуатационная приёмка |

Codex не обязан повторять полный регрессионный набор после каждой правки. Выбирать проверки по затронутым модулям, контрактам и рискам. Если применимый CI выполняет проверку текущего SHA, использовать его результат вместо повторного прогона в Codex; локально запускать нужный тест для диагностики, воспроизведения или проверки исправления. Результаты старого SHA не заменяют проверку нового.

При отсутствии применимого CI выполнить необходимые адресные проверки в доступной среде Codex. Не создавать специальную инфраструктуру, не настраивать отдельную постоянную среду разработки и не устанавливать тяжёлые инструменты исключительно ради формального прохождения регламента. Если окружение мешает проверке, зафиксировать конкретное ограничение, невыполненную проверку и риск. Не подменять проверку ослаблением теста или заявлением об успехе.

На RELEASE запрещены разработка, автоматические тестовые наборы, CI runner и установка диагностических зависимостей (Playwright, Chromium, Node.js и т. п.). Не переносить тест туда из-за ограничений Codex. Рабочие зависимости приложения устанавливаются по deployment.md.

## Существующие проверки

Все постоянные тесты и фикстуры находятся в probe/. Основные тесты используют unittest, pytest не требуется. Внешние сервисы подменяются; тестовые данные и рабочие каталоги изолируются от production.

| Скрипт | Покрытие |
| --- | --- |
| `probe/check_batch.py` | Общая партия, сопоставление, отсрочка, дубли, VK/default media, IMAP-флаги, ошибки |
| `probe/check_logging.py` | Журналы, очистка и удержание lock, ошибки, режимы запуска |
| `probe/check_webui_api.py` | Сессии, CSRF, конфигурация, Debug, запуск, cron, прокси, история, SSE, отдельные процессы |
| `probe/check_webui_browser.py` | Реальный HTTP/SSE на изолированном стенде, вход/выход, просмотрщики, настройки, контролы |
| `probe/check_webui_journal.py` | Chromium с подменёнными API/SSE, блоки журнала, масштаб, темы, фильтры, экспорт, resync |
| `probe/serve_webui_fixture.py` | Временный Waitress-стенд с подставным конвейером |

## Выбор проверок

| Изменение | Применимые проверки |
| --- | --- |
| Документация | Diff, ссылки, соответствие действующему коду; функциональные тесты не нужны |
| HTML/CSS | Затронутые визуальные и браузерные сценарии |
| JavaScript | Синтаксис и затронутые браузерные сценарии |
| HTTP API | check_webui_api; браузерный тест при изменении клиентского контракта |
| Обработка материалов | check_batch; check_logging при влиянии на поток, ошибки и журнал |
| Журналирование | check_logging, check_webui_api; check_webui_journal при изменении представления |
| Блокировки, запуск | check_batch, check_logging, check_webui_api |
| Существенные изменения нескольких подсистем | Объединить применимые проверки; полный набор при широком риске регрессии |

Таблица определяет область проверки, а не требует дважды запускать целые скрипты. Codex может воспроизводить отдельный unittest-сценарий; применимый полный CI-прогон используется для окончательной регрессии. При изменении исправления повторить затронутый тест на новом коде. Не гонять неизменившиеся проверки повторно без причины.

## Команды

Из корня репозитория в изолированной среде с Python и requirements.txt:

```sh
python probe/check_batch.py
python probe/check_logging.py
python probe/check_webui_api.py
```

Это полный основной набор, не обязательный для каждой небольшой задачи. Проверки синтаксиса при соответствующих изменениях:

```sh
python -m compileall -q *.py probe
sh -n cron-newsbot.sh
for file in webui/index_files/*.js; do
    node --check "$file" || exit 1
done
git diff --check
```

Node.js нужен только для JS syntax, не является рабочей зависимостью. Для браузерных проверок при наличии Playwright и Chromium в диагностической среде:

```sh
# Терминал 1: оставить временный сервер работающим.
python probe/serve_webui_fixture.py --prefix /newsbot --port 18081
# Терминал 2: ROOT — напечатанный стендом временный каталог.
python probe/check_webui_browser.py --fixture-root "$ROOT" --url http://127.0.0.1:18081/newsbot/ --chromium /usr/bin/chromium
python probe/check_webui_journal.py --chromium /usr/bin/chromium
```

Указать фактический путь к Chromium, если отличается; после проверки остановить временный стенд. Никогда не направлять браузерный probe на действующий Newsbot. Проверки системных блокировок, отдельных процессов и localhost требуют поддержки соответствующих операций средой. Офлайн-стенд не подтверждает реальный cron/systemd, HTTPS-прокси, Pandoc и доступность внешних сервисов.

## Приёмка и отчёт

До передачи изменений владельцу — review diff и применимые проверки конкретного SHA. Для переноса кода в main и развёртывания действуют правила AGENTS.md. При наличии обязательного CI подтвердить его успешное завершение для принимаемого изменения. Не считать недоступную проверку пройденной.

На RELEASE выполнять непосредственную проверку по deployment.md: службы, HTTPS, авторизация, журнал и статус расписания; визуально проверить затронутый интерфейс. Не ждать следующего cron-запуска и не запускать реальную публикацию как health check. Проверку живых IMAP/VK/WordPress и полного цикла проводить только по отдельному согласованию владельца, если она необходима; не считать обязательным этапом обычного обновления.

В задаче, PR или рабочем чате указать:

- Ветка, SHA, среда.
- Проверки, результаты и ссылки на CI при наличии.
- Обнаруженные регрессии, невыполненные проверки и причины.
- Итог: пройдено / не пройдено / частично проверено.

Не добавлять историю прогонов в этот документ; не публиковать рабочие секреты, письма и журналы.
