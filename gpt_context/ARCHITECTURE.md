# zanevka newsbot Architecture

Краткая карта архитектуры проекта. Обновлять при добавлении новых модулей и изменении границ ответственности существующих.

## Общий поток

prelaunch -> партия EML -> общие DOCX/изображения/VK -> integrity_check -> публикация или однократная отсрочка -> очистка.

## Python Newsbot: основные модули

- `prelaunch.py` — единая внешняя точка запуска: OS-lock и режим по `delayed.publish`.
- `main.py` — один конвейер подготовки и публикации партии.
- `integrity_check.py` — чистая функция анализа полноты с существующим `find_matching_images()`.
- `eml_parser.py` / `eml_links.py` — письмо, вложения и ссылки.
- `news_parser.py` — формирование структуры новости.
- `image_manager.py` — изображения и загрузка медиа.
- `vk_video.py` — данные и preview VK.
- `wordpress.py` — взаимодействие с WordPress.
- `config.py` — локальная конфигурация; секреты не должны попадать в Git.
- `log.py` — представление событий и хранение UTF-8 журналов запусков. Получает
  готовые значения от `main.py` и `mail_downloader.py`; не разбирает stdout,
  не определяет принадлежность изображений и не вызывает рабочие модули.

### Журнал запуска

- `prelaunch.py` получает process lock до импорта конвейера, удерживает
  `flags/.newsbot.running`, читает свежий config.py, один раз настраивает и
  активирует журнал до почты. `main.py` сообщает этапы/результаты и возвращает
  явный результат пустоты. Итог идёт после очистки; лаунчер закрывает журнал,
  затем удаляет running и последним освобождает общий lock.
- `download_news_batch()` фиксирует список писем и скачивает все до подготовки;
  его activate() совместим и не создаёт второго файла.
- Каждый запуск, включая успешную пустую проверку, имеет один UTF-8 журнал.
  После успешного закрытия обычная пустая проверка без WARNING/ERROR получает
  метку в flags. Сам бот удаляет её журнал в начале последующего запуска после
  LOG_EMPTY_MIN_AGE_SECONDS (default 600). Пустой повтор с погашением
  delayed.publish сохраняется; потеря метки означает обычное LOG_* хранение.
- Заголовок: `YYYY-MM-DD HH:MM:SS [INFO|OK|WARNING|ERROR] текст`.
  Каждая физическая строка подробностей имеет начальную табуляцию. Отступленные
  строки наследуют метаданные заголовка; новый уровень требует нового блока.
- `log.py` содержит общий вывод заголовка/подробности и небольшие функции
  представления готовых отчётов. Рабочие решения и готовность продолжать
  обработку остаются у конвейера. Исключения содержат traceback; при невозможности
  писать активный журнал `LogWriteError` проходит через обработчики ошибок
  отдельных материалов и останавливает запуск.
- Настройки хранения — `LOG_DIR`, `LOG_RETENTION_DAYS`, `LOG_MAX_TOTAL_MB`
  и `LOG_EMPTY_MIN_AGE_SECONDS` в локальном `config.py`, с defaults `logs`,
  30 дней, 200 МиБ и 600 секунд для старого конфига.
  Стандартные сообщения сбрасываются сразу, активный файл не удаляется очисткой.
- Один общий читатель webui_server.py читает готовые строки по байтовым позициям
  и раздаёт их через SSE с историей/курсором; API не вызывает log.setup/очистку.
  Контракт и ограничения буферов: webui/API.md, эксплуатация: webui/DEPLOYMENT.md.

## Python Newsbot: основные директории

- `probe/` — единственное место для тестовой и диагностической обвязки Python Newsbot (тесты, проверочные скрипты и их тестовые данные). Новые тесты и утилиты не размещать в корне рядом с рабочими модулями.
- `downloaded_eml/` и `extracted_images/` — директории временных данных обработки.
- `flags/` — все служебные флаги и lock-файлы (исключён из Git).
- `logs/` — журналы запусков (исключены из Git); относительный путь настроек
  журналирования считается от каталога проекта, а не от текущего каталога cron.

### Размещение служебных флагов — 2026-10-23

Все служебные флаги и lock-файлы хранятся в `flags/` внутри каталога проекта.
Пути определяются от расположения Python-модулей, независимо от cwd или cron.
`prelaunch.py` автоматически создаёт каталог перед получением блокировки.

| Файл | Назначение |
| --- | --- |
| `flags/delayed.publish` | Одноразовый признак повторного прохода |
| `flags/.main.lock` | Файл системной блокировки единственного экземпляра |
| `flags/.newsbot.disabled` | Запрет будущих cron-запусков |
| `flags/.newsbot.running` | Удерживаемая OS-блокировка внешнего запуска |
| `flags/*.empty.json` | Машинные метки завершённых обычных пустых проверок |

Новые служебные флаги размещаются в том же каталоге. При обновлении существующие
`delayed.publish` и `.newsbot.disabled` из корня проекта переносит администратор
в `flags/` между запусками; автоматическая миграция не выполняется.

## WebUI

- `webui/index.html` — разметка интерфейса: журнал, управление запуском, вкладки настроек почты, WordPress, VK и расписания.
- `webui/index_files/script.js` — привязка существующих контролов к API, журнал/курсор, форма настроек и поведение окна.
- `webui/index_files/theme_switcher.js` — переключение и сохранение цветовой темы.
- `webui/index_files/*.css` и `*.svg` — внешний вид, иконки и логотип.
- `webui/README.md` — подробности текущего поведения WebUI.

WebUI обслуживается `webui_server.py`: Flask/Waitress, одна учётная запись,
страница login, CSRF, ограниченная cookie-сессия, config.py с ревизией и один
читатель файлов/SSE. Сервер запускает отдельный `sys.executable -u prelaunch.py`
с cwd проекта; основной конвейер в API не импортируется.

## Границы интеграции

API отвечает за HTTP/сессии, принятый запрос запуска до появления флажка,
безопасное редактирование литералов, чтение статуса и журналов. Источник обычного
статуса — блокировка `.newsbot.running`, а окончательная защита партии —
`.main.lock` лаунчера. Debug атомарно очищает flags кроме `.main.lock` через
helper лаунчера, без вызова конвейера/IMAP. Все флаги остаются в flags/.

Бот работает без API; cron вызывает POSIX-обёртку `cron-newsbot.sh`, которая
проверяет disabled и запускает prelaunch. API не редактирует crontab/службы.
На Windows — Windows/manual. Журнал и Python-конфиг остаются самостоятельными.
Локальный JSON сервера содержит доступ/хеш/ключ и HTTP-параметры, исключён из Git.

Внешний HTTPS завершает существующий Caddy/Apache/nginx, Waitress по умолчанию
слушает loopback:8081; prefix сохраняется в upstream. Доверие forwarding headers
только явным IP непосредственного прокси. Запуск HTTP возможен явным loopback
режимом. SSE: опрос 0,5с, heartbeat 10с, bounded history/replay/очереди, явный
resync, стабильные идентичности строк, повторная проверка сессии каждую секунду.
В основном WebUI не меняются HTML/CSS/подписи; только данные/обработчики.
Новые элементы — лишь отдельный login. Logout и Debug пока доступны только API.

## Партия и проверка полноты

Реализован один конвейер `prelaunch → main → integrity_check → main`.
`prelaunch.py` получает существующую системную блокировку `flags/.main.lock`
и вызывает `main.main(defer_if_incomplete=..., delayed_publish_file=...)`
в том же процессе. Отсутствующий `delayed.publish` разрешает отсрочку;
существующий флаг означает повторный режим и погашается в начале `main.py`.
Оба служебных файла находятся в `flags/` относительно каталога проекта. Прямой CLI-запуск
`main.py` перенаправляется в диспетчер. Отдельного `first_main.py` нет.

`download_news_batch()` один раз ищет подходящие UNSEEN-письма, скачивает все
и подтверждает SEEN до возврата. `main.process_batch()` извлекает все EML,
оставляет первые вложения с одинаковыми именами и собирает общую партию.
Тексты писем не склеиваются: VK из каждого EML ищется отдельно с общим
списком документов. Ссылка из DOCX сохраняет приоритет.

`integrity_check.check_integrity()` возвращает `matches`, `unmatched_images`,
`ambiguous_images`, `documents_without_media` и `incomplete`. Он переиспользует
существующее сопоставление имён, не обращается к IMAP, журналу, флагам или WP.
Отчёт строится в обоих режимах; только реакция на неполноту зависит от режима.
Неоднозначные сопоставления остаются предупреждением по прежним правилам.

При первой неполной партии `main.py` подтверждает UNSEEN для всех её писем,
затем создаёт `delayed.publish` и завершает запуск до загрузок в WordPress.
Основания — непривязанные изображения или DOCX без картинок и без VK.
Повторная проверка заново скачивает UNSEEN-письма и не откладывает их из-за
неполноты. Файлы и состав партии между запусками не сохраняются.

Стандартная картинка ищется по точному имени `s600xu_2x.webp` в
`image_manager.py` через paginated Media API; успешный ID кэшируется на партию.
Она используется только при отсутствии сопоставленных картинок и VK.
Для новости с VK без своих картинок отсутствие/ошибка preview означает пропуск
этой новости. При своих картинках прежнее продолжение после ошибки VK сохранено.

Ошибка скачивания после retry, чтения/подготовки материалов или записи журнала
останавливает партию; отсрочка не создаётся. MIME-разбор сообщает о структурных
дефектах, ошибках декодирования и пустых DOCX/изображениях. Ошибка отдельной
новости внутри публикации не прерывает остальные. Временные файлы очищаются
при любом завершении, журнал закрывается до освобождения lock. Восстановление
писем при необходимости делает администратор; автоматического отката нет.

Кнопка Debug и её серверная операция остаются будущей задачей интеграции.
WebUI этой ветки не изменён. Подробные правила и ограничения — в `DECISIONS.md`.

## Правила изменений

1. Предпочитать минимальные локальные изменения широкому рефакторингу.
2. Не менять контракты между модулями без отдельного решения.
3. Новую ответственность сначала размещать в существующем подходящем модуле. Если подходящего модуля нет - запрашивать создание нового модуля.
4. После архитектурного изменения обновлять этот файл и при необходимости `DECISIONS.md`.
