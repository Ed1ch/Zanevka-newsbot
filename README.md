# Zanevka Newsbot

## Цель проекта

**Zanevka Newsbot** — проект автоматической подготовки и публикации новостей из входящих писем на WordPress-сайте `zanevkaorg.ru`. Обработка выполняется Python-модулями; каталог `webui/` содержит существующий интерфейс управления и просмотра журналов, подключённый к Flask/Waitress API.

Основной pipeline:

```text
prelaunch -> загрузка партии EML -> общие DOCX/картинки/VK -> integrity_check -> публикация или отсрочка -> cleanup
```

Ошибка отдельной новости на этапе публикации не останавливает следующие новости партии. Ошибка скачивания после всех retry или ошибка подготовки партии останавливает запуск до публикации. Временные EML и изображения удаляются при завершении, включая отсрочку и исключение.

## Python Newsbot: основные модули

- `prelaunch.py` — внешняя точка запуска: общая системная блокировка и выбор первого/повторного режима.
- `main.py` — один конвейер сборки и публикации всей партии.
- `integrity_check.py` — анализ полноты по существующим правилам сопоставления; возвращает отчёт без сетевых и файловых операций.
- `eml_parser.py` / `eml_links.py` — письмо, вложения и ссылки.
- `news_parser.py` — формирование структуры новости.
- `image_manager.py` — изображения и загрузка медиа.
- `vk_video.py` — данные и preview VK.
- `wordpress.py` — взаимодействие с WordPress.
- `config.py` — локальная конфигурация; секреты не должны попадать в Git.
- `log.py` — форматирование и хранение текстовых журналов запусков.

## Запуск и отложенная публикация

```sh
python prelaunch.py
```

Эту команду использовать для ручного запуска, задания cron (раз в два часа)
и API. Старый `python main.py` делегирует запуск в `prelaunch.py`,
поэтому тоже получает общую блокировку. Программный `main.main()` является
внутренним вызовом конвейера; внешние Python-клиенты вызывают `prelaunch.main()`.

Все служебные флаги и lock-файлы находятся в `flags/` внутри папки проекта,
независимо от текущего каталога запуска. Каталог создаётся автоматически
и исключён из Git. При обновлении старый `delayed.publish` из корня нужно
перенести в `flags/delayed.publish` между запусками бота; так же переносится
`.newsbot.disabled`, если он использовался во внешней Unix-обёртке.

`prelaunch.py` удерживает существующую OS-блокировку `flags/.main.lock` до завершения
обработки, очистки и закрытия журнала. Оставшийся файл не означает занятость;
параллельный запуск при занятой блокировке молча завершается.

- Нет `flags/delayed.publish` — первый проход, разрешена одна отсрочка.
- Есть `flags/delayed.publish` — повторный проход без новой отсрочки. Флаг погашается
  в начале конвейера под блокировкой, включая пустую проверку или последующую
  техническую ошибку. Источник запуска на выбор режима не влияет.

Список подходящих UNSEEN-писем фиксируется один раз в начале проверки.
После скачивания всех EML документы и изображения объединяются; одинаковые
полные имена без учёта регистра сохраняются только в первом экземпляре
(по UID письма и порядку вложений), даже если содержимое разное. Дубли дают
WARNING и сами по себе не вызывают остановку или отсрочку.

Проверка после определения VK откладывает всю партию при наличии непривязанных
картинок либо DOCX одновременно без картинок и без VK. Сначала письмам
возвращается UNSEEN с подтверждением IMAP, затем создаётся `delayed.publish`.
До этого решения загрузки медиа и публикации WordPress не выполняются.
EML, изображения и отдельный список партии между запусками не сохраняются.
На следующем запуске старые и новые UNSEEN-письма скачиваются заново.

Предполагается, что за интервал расписания в два часа остальные материалы
успеют прийти. Сам флаг время не отсчитывает; ручной запуск может сократить
ожидание. Прочитанные или перемещённые администратором письма пропускаются.

Для новости без картинок и без VK используется ID существующего
`s600xu_2x.webp` из медиатеки. Поиск проверяет точное имя и страницы результатов;
успешный ID кэшируется на партию. Файл не загружается заново и не входит в галерею.
Если есть VK, стандартная картинка запрещена: для новости без собственных
картинок отсутствие или ошибка загрузки preview приводит к пропуску этой
новости. При наличии своих картинок сбой VK сохраняет прежнее продолжение
публикации. Ссылка внутри DOCX имеет приоритет перед ссылкой из письма.

При полном успехе все письма партии перемещаются в корзину. При ошибках
публикации письма остаются SEEN в INBOX. Ошибки подготовки не создают флаг
отсрочки; уже зарезервированные письма также остаются SEEN. Автоматический
откат почты не выполняется, восстановление при необходимости делает
администратор вручную. Debug реализован как авторизованный `POST /api/debug/reset-flags` под общим lock; кнопка появится в отдельном UI-проходе. Он не восстанавливает письма.

## Журналирование

`main.py` и `mail_downloader.py` сообщают о событиях непосредственно через
`log.py`; перехвата и разбора stdout нет. Рабочие модули возвращают обычные
данные, а `log.py` оформляет заголовки и подробности. Сопоставление изображений,
парсинг документов, запросы к VK и WordPress в `log.py` не выполняются.

После получения общей блокировки **prelaunch.py** один раз настраивает
и активирует журнал до импорта конвейера/проверки почты. Все сообщения, включая
старт и успешную пустую проверку, пишутся в один UTF-8
`logs/DDMMYYYY_HHMMSS_RRRRRR.txt` с немедленным flush. Имя содержит дату и время
создания, затем первые 6 шестнадцатеричных символов UUID4, например
`26102026_132015_a7f2c9.txt`.
Повторный экземпляр при занятой `.main.lock` молчит и файла не создаёт.
Журнал закрывается после очистки и итога, затем снимается `.newsbot.running`
и последним освобождается `.main.lock`. Сервер только читает файлы.

Обычная успешная пустая проверка без WARNING/ERROR получает машинную метку
в flags после закрытия. Сам бот в начале следующего запуска удаляет помеченные
неизменившиеся журналы возрастом от `LOG_EMPTY_MIN_AGE_SECONDS=600` секунд.
Пустой повтор с погашением delayed.publish сохраняется как содержательный.
Потеря метки, включая Debug, означает обычное хранение по LOG_*.
API не удаляет журналы; срок — окно чтения, а не гарантия доставки выключенной панели.

Формат — обычный UTF-8 текст. Заголовок блока начинается с первой позиции:

```text
2026-10-21 12:00:00 [INFO] ПРОВЕРКА INBOX imap.example.invalid ...
    Найдено письмо UID 25: ЗГП
```

В настоящем файле каждая строка подробностей начинается **табуляцией**, включая
многострочный embed и traceback. Пустые строки служат визуальными разделителями;
следующий заголовок начинает новый блок. Используется системное время сервера
без пересчёта по времени браузера. Каждая готовая строка завершается переносом;
каждое сообщение сразу сбрасывается из буфера записи. Попытка скачивания
выводится перед сетевой операцией, результат — следующей строкой: уже записанный
текст не переписывается ради дописывания `OK` в конец той же строки.

Уровни: `INFO` — ход работы; `OK` — единственный содержательный успешный итог;
`WARNING` — проблема, после которой выполнение продолжается; `ERROR` — запуск
дальше выполнять невозможно. Ошибка одной новости не прерывает остальные.
Неудачное скачивание после всех retry останавливает партию с итоговым
`ERROR`; продолжения со следующим письмом в пакетном режиме нет. Штатная
отсрочка имеет отдельный итог `WARNING` «публикация отложена». Пропуск отдельной
новости даёт `WARNING`; информационные предупреждения о дублях или сбое VK
при наличии своих картинок могут сопровождать `OK`, если все новости обработаны.

Исключения сохраняются с цепочкой вызовов, чтобы
был виден исходный файл и место ошибки. Значения паролей и токенов из конфигурации
маскируются. Ошибка записи активного журнала останавливает конвейер; диагностика
остаётся в консоли, выполняется завершающая очистка и освобождается process lock.

Параметры задаются только в локальном `config.py` (пример есть в
`config.example.py`):

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `LOG_DIR` | `"logs"` | Каталог журналов; относительный путь считается от каталога проекта |
| `LOG_RETENTION_DAYS` | `30` | Срок хранения в днях, положительное число |
| `LOG_MAX_TOTAL_MB` | `200` | Предел общего объёма в МиБ, положительное число |
| `LOG_EMPTY_MIN_AGE_SECONDS` | `600` | Минимальный возраст обычного помеченного пустого журнала |

Существующий `config.py` без этих переменных продолжает работать с
указанными значениями по умолчанию. Очистка выполняется при настройке и закрытии
журналирования: сначала удаляются старейшие завершённые файлы при превышении
возраста или объёма. Активный файл не удаляется и может временно превышать лимит;
посторонние `.txt` и символьные ссылки очистка не затрагивает. Каталог `logs/`
исключён из Git. До настройки логирования ошибки импорта/синтаксиса остаются
обычными сообщениями Python в stderr.

API передаёт историю последних десяти журналов и новые готовые строки через
SSE с курсором, контекстом блока и явной повторной синхронизацией. Серверное время
и уровни сохранены; HTML из журнала отображается только как текст.

### Проверка без почты и публикаций

```sh
python probe/check_logging.py
python probe/check_webui_api.py
```

Проверка использует `unittest` стандартной библиотеки, подставной конфиг и
подменяет операции IMAP/WordPress. Настоящие почтовые ящики и сайт не изменяются.
Проверяются пустой и успешный запуск, несколько писем, ошибки и продолжение,
retry, освобождение блокировки, закрытие файлов, хранение и читаемость текста
по частям. `check_webui_api.py` проверяет авторизацию/CSRF, настройки, Debug, SSE, прокси/префикс и реальные отдельные процессы. `check_batch.py` остаётся прежней необязательной проверкой пакетной ветки; ради интеграции не менялся и не запускался. Для настоящего запуска по-прежнему нужны зависимости из
`requirements.txt` и Pandoc; Unix/Windows требуют проверки на целевой машине.

Первый запуск, команды Windows/Unix, локальный HTTP, настройка HTTPS/префикса,
Caddy/Apache, cron и ручные API-команды: **[webui/DEPLOYMENT.md](webui/DEPLOYMENT.md)**.

Быстрый запуск после установки зависимостей и заполнения локального config.py:

```sh
python webui_server.py init-admin
python webui_server.py serve --local-http
```

Откройте http://127.0.0.1:8081/ и войдите. Для эксплуатации настройте внешний
HTTPS-прокси и `webui_server.local.json`, затем запускайте без --local-http.

## Разработка

GitHub — canonical repository проекта. Перед изменением кода следует ориентироваться на актуальное состояние репозитория, а не на старый контекст чатов.

Рабочая среда — Windows 10 / Python 3.13. Проект развивается небольшими проверяемыми изменениями.

Целевые ОС — Windows 10, Debian Linux и FreeBSD с единой кодовой базой. Совместимость с FreeBSD и эксплуатационной средой требует проверки. Периодический запуск Newsbot планируется через cron на Unix (раз в 2 часа). На Windows WebUI не будет управлять Планировщиком заданий: предусмотрен режим `Windows/manual`; при необходимости расписание настраивается отдельно средствами ОС. API проверен на Debian 13/Python 3.13.5; Windows 10 и FreeBSD, реальные службы/proxy и внешние сервисы нужно проверить при развёртывании.
