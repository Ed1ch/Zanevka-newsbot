# Zanevka Newsbot

## Цель проекта

**Zanevka Newsbot** — проект автоматической подготовки и публикации новостей из входящих писем на WordPress-сайте `zanevkaorg.ru`. Обработка выполняется Python-модулями; каталог `webui/` содержит веб-интерфейс для будущего управления программой и просмотра журнала.

Основной pipeline:

```text
почта -> .eml -> парсинг текста/ссылок/изображений -> VK -> подготовка контента -> WordPress -> cleanup
```

Ошибка при обработке одной новости не должна останавливать обработку следующих писем. Временные `.eml` и извлечённые изображения должны очищаться после каждой итерации, в том числе при ошибке.

## Python Newsbot: основные модули

- `main.py` — orchestration: связывает этапы обработки.
- `eml_parser.py` / `eml_links.py` — письмо, вложения и ссылки.
- `news_parser.py` — формирование структуры новости.
- `image_manager.py` — изображения и загрузка медиа.
- `vk_video.py` — данные и preview VK.
- `wordpress.py` — взаимодействие с WordPress.
- `config.py` — локальная конфигурация; секреты не должны попадать в Git.
- `log.py` — форматирование и хранение текстовых журналов запусков.

## Журналирование

`main.py` и `mail_downloader.py` сообщают о событиях непосредственно через
`log.py`; перехвата и разбора stdout нет. Рабочие модули возвращают обычные
данные, а `log.py` оформляет заголовки и подробности. Сопоставление изображений,
парсинг документов, запросы к VK и WordPress в `log.py` не выполняются.

При обнаружении подходящего UNSEEN-письма журнал открывается **до скачивания**.
Все письма одного запуска попадают в один файл
`logs/newsbot_YYYYMMDD_HHMMSS_microseconds_unique.txt`. Штатная проверка без
новых писем не создаёт ни файла, ни каталога журналов. Предупреждение или ошибка
до обнаружения письма тоже сохраняются: отсутствие подходящих писем не должно
скрывать проблему проверки. Повторный запуск при занятой `.main.lock` молча
завершается без отдельного журнала.

Сообщения одновременно выводятся в консоль. В файл попадает вывод начиная с
текущего блока проверки INBOX; более ранние стартовые сообщения остаются только
в консоли. Чтобы первая сохранённая подробность не осталась без заголовка,
`log.py` сохраняет только текущий заголовок и записывает его при открытии файла.
Буфера всех сообщений пустой проверки нет.

Формат — обычный UTF-8 текст. Заголовок блока начинается с первой позиции:

```text
2026-10-21 12:00:00 [INFO] ПРОВЕРКА INBOX imap.example.invalid ...
    Найдено письмо UID 25: ЗГП
```

В настоящем файле каждая строка подробностей начинается **табуляцией**, включая
многострочный embed и traceback. Пустые строки служат визуальными разделителями;
следующий заголовок начинает новый блок. Используется системное время сервера
без пересчёта по времени браузера. Каждая готовая строка завершается переносом;
каждое сообщение сразу сбрасывается из буфера записи. Попытка скачивания
выводится перед сетевой операцией, результат — следующей строкой: уже записанный
текст не переписывается ради дописывания `OK` в конец той же строки.

Уровни: `INFO` — ход работы; `OK` — единственный содержательный успешный итог;
`WARNING` — проблема, после которой выполнение продолжается; `ERROR` — запуск
дальше выполнять невозможно. Ошибка одной новости не прерывает остальные.
Неудачное скачивание после всех retry учитывается в итоговом счётчике отдельно
от ошибок обработки. При пропущенных материалах/письмах итог имеет уровень
`WARNING`; допустимые предупреждения вроде непривязанной картинки или сбоя VK
могут сопровождать `OK`, если все новости удалось обработать.

Исключения сохраняются с цепочкой вызовов, чтобы
был виден исходный файл и место ошибки. Значения паролей и токенов из конфигурации
маскируются. Ошибка записи активного журнала останавливает конвейер; диагностика
остаётся в консоли, выполняется завершающая очистка и освобождается process lock.

Параметры задаются только в локальном `config.py` (пример есть в
`config.example.py`):

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `LOG_DIR` | `"logs"` | Каталог журналов; относительный путь считается от каталога проекта |
| `LOG_RETENTION_DAYS` | `30` | Срок хранения в днях, положительное число |
| `LOG_MAX_TOTAL_MB` | `200` | Предел общего объёма в МиБ, положительное число |

Существующий `config.py` без этих трёх переменных продолжает работать с
указанными значениями по умолчанию. Очистка выполняется при настройке и закрытии
журналирования: сначала удаляются старейшие завершённые файлы при превышении
возраста или объёма. Активный файл не удаляется и может временно превышать лимит;
посторонние `.txt` и символьные ссылки очистка не затрагивает. Каталог `logs/`
исключён из Git. До настройки логирования ошибки импорта/синтаксиса остаются
обычными сообщениями Python в stderr.

API и чтение настоящих журналов в WebUI пока не реализованы. Будущий API должен
распознавать заголовки и строки продолжения, передавать готовые строки сразу и
восстанавливать контекст блока при переподключении. Формат файла менять для
этого не требуется.

### Проверка без почты и публикаций

```sh
python probe/check_logging.py
```

Проверка использует `unittest` стандартной библиотеки, подставной конфиг и
подменяет операции IMAP/WordPress. Настоящие почтовые ящики и сайт не изменяются.
Проверяются пустой и успешный запуск, несколько писем, ошибки и продолжение,
retry, освобождение блокировки, закрытие файлов, хранение и читаемость текста
по частям. Для настоящего запуска по-прежнему нужны зависимости из
`requirements.txt` и Pandoc; Unix/Windows требуют проверки на целевой машине.

## Python Newsbot: основные директории

- `probe/` — вся тестовая и диагностическая обвязка Python Newsbot: тесты, проверочные скрипты и связанные с ними тестовые данные. Новую тестовую обвязку размещать здесь, а не в корне репозитория.
- `downloaded_eml/` и `extracted_images/` — директории временных данных обработки.

Подробные границы ответственности модулей описаны в `gpt_context/ARCHITECTURE.md`.

## WebUI

- `webui/index.html` — разметка интерфейса с журналом, элементами управления и вкладками настроек.
- `webui/index_files/` — JavaScript, CSS и SVG-ресурсы.
- `webui/README.md` — описание функций и структуры WebUI.
- `webui/AGENTS.md` — специальные правила работы AI с интерфейсом.

**Текущее состояние:** WebUI — самостоятельный статический макет без связи с Python Newsbot, предназначенный для проверки дизайна и демонстрации интерфейса. Кнопка запуска воспроизводит демонстрационные сообщения, а настройки макета (кроме секретных полей) сохраняются в браузере. Настоящее управление ботом и получение его журнала ещё не реализованы.

## Разработка

GitHub — canonical repository проекта. Перед изменением кода следует ориентироваться на актуальное состояние репозитория, а не на старый контекст чатов.

Рабочая среда — Windows 10 / Python 3.13. Проект развивается небольшими проверяемыми изменениями.

Целевые ОС — Windows 10, Debian Linux и FreeBSD с единой кодовой базой. Совместимость с Unix пока требует тестирования. Периодический запуск Newsbot планируется через cron на Unix (раз в 2 часа). На Windows WebUI не будет управлять Планировщиком заданий: предусмотрен режим `Windows/manual`; при необходимости расписание настраивается отдельно средствами ОС. WebUI и будущая связка с Python также должны работать на целевых платформах; интеграция и проверка на Unix пока впереди.
